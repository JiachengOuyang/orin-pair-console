# Orin Pair Console

当前版本：**0.9.0**

> 本文是完整手册，覆盖操作细节、安全边界和验证记录。项目概览和最短启动见仓库根目录的 [README.md](../README.md)。

Windows 和 Ubuntu（Orin NX 或虚拟机）之间的可视化配对工具。程序启动后自动检测系统，让你选这台机器是**控制端**还是**被控端**：控制端负责扫描、输码、写 ssh 配置；被控端显示配对码、管理公钥和网络。两端都能解除配对。

连接方式支持 USB 直连、同一局域网，以及跨网段的 Tailscale 组网（v0.5.0 起，控制端可自动发现对端）。

只用 Python 3 标准库，界面是程序自己提供的本地网页，不需要装 Qt、Electron 或任何前端依赖。

## 文件

| 文件 | 作用 |
|-|-|
| `start.sh` | 顶层，Linux/Ubuntu 入口，自动检测系统 |
| `start.bat` | 顶层，Windows 入口，双击运行 |
| `app/pair_console.py` | 主程序，默认进入角色选择；也可用 `--role` 直接指定 |
| `app/pairui/` | 网页界面：角色选择、控制端、被控端 |
| `app/runtime/` | 程序自己创建的数据目录：状态、密钥、ssh 配置、日志、临时文件（详见下文） |
| `app/setup.sh` | 命令行环境准备（和页面「环境准备」等价），另带 sshd 加固和命令审计；不新建账号 |
| `app/README.md` | 本文档 |
| `app/agent远程连接-优化版.md` | 更完整的 ssh、账号、ROS 2 说明 |

顶层只留 `start.bat`、`start.sh` 两个入口，其余都在 `app/` 里。把整个目录拷到目标机器时，两个入口和 `app/` 要一起拷。

## 快速开始

**被控端（Ubuntu / Orin）：**

```bash
./start.sh
```

进入页面后点“被控端”。普通用户就能跑：配对、换码、解除配对都正常，只会把自己的公钥写进自己的 `authorized_keys`。要改网络或装环境时，在「环境准备」里输入登录密码切换为 root，程序会以 root 自动重启，页面自动恢复，不需要回终端重开。没接显示器时，终端会打印 `http://<ip>:8770`，在 Windows 浏览器里打开后再选“被控端”。

第一次用可以直接在页面「环境准备」里点“安装 / 修复”：装 `openssh-server`、`tmux`、`avahi`，启用 ssh 和 avahi，准备 `~/.ssh`（700/600），把目标账号加入 `dialout`。也可以在终端跑 `sudo bash app/setup.sh`，效果相同，另外还带 `--harden`、`--audit` 两个进阶选项。

`app/setup.sh` 不再新建账号，默认配置 sudo 的发起用户；目标账号不存在会直接报错，可用 `--user <已有账号>` 指定。

也可以直接跑，不经过选择页：

```bash
python3 app/pair_console.py --role orin --target-user <当前用户> --bind 0.0.0.0 --port 8765
```

角色页会标出“普通用户模式”，被控端页面顶部也会提示可以在页面里切 root。

**控制端（Windows）：**

```bat
start.bat
```

进入页面后点“控制端”。端口 `8766`，只监听 `127.0.0.1`，不接受远程访问。

「运行环境」会检测 `ssh.exe`（系统自带的 OpenSSH Client，或 Git for Windows 里的）。没找到时页面会显示「安装 SSH 客户端」按钮：点它通过 Windows 可选功能安装 `OpenSSH.Client`，会弹 UAC；也可以自己装 Git for Windows，程序会自动使用它自带的 ssh。装好后不用重启程序，页面刷新就会显示路径。

**控制端（Ubuntu 桌面，可选）：** 用普通用户运行 `./start.sh`，再点“控制端”。以 root 启动时控制端会被禁用，避免写 root 的 `~/.ssh`。

端口分配：角色选择 `8770`（监听 `0.0.0.0`，方便远程选“被控端”），控制端 `8766`，被控端 `8765`。选择后本进程会直接切换成对应角色，选择页自动关闭。

想跳过选择页，直接给 `--role` 即可：`./start.sh --role orin`（普通用户；要改网络可用页面里的切换，或 `sudo` 启动）；Windows 用 `start.bat --role windows`。

**被控端页面上：**

0. 「环境准备」：看 sshd / tmux / avahi / `.ssh` 权限 / dialout 是否就绪，缺什么点“安装 / 修复”。
1. 选连接方式。USB device 和 mDNS 只做检测，不改 IP；静态 IP 会调用 `nmcli` 改指定连接。
2. 记下 6 位配对码。配对成功后自动更换；也可以点“更换”。
3. 「远程组网」卡片看 Tailscale 是否安装、是否连上，以及本机的 `100.x` 地址（可选，跨网段才需要）。
4. “已配对设备”里可以随时解除某一台。

**控制端页面上：**

1. 扫描（默认试 `192.168.55.1`、`orin.local`，以及本机 Tailscale 在线对端；也可手填地址和端口）。
2. 选结果，输入被控端页面上的 6 位配对码，点“完成配对”。
3. 配对成功后可以“测试连接”“更新指纹”“复制 ssh 命令”“解除配对”。

## 配对做了什么

所有程序产生的文件都在入口同级的 `app/runtime/` 里（即 `app/pair_console.py` 旁边），不再改用户的 `~/.ssh`。目录不可写时（比如程序放在只读位置）会退回 `~/.orin-pair/<角色>`，启动时会打印实际路径。

**控制端写入 `app/runtime/controller/`：**

- `ssh/id_ed25519`：没有就生成一把无口令密钥（复用已有的）。
- `ssh/config`：只维护一段带标记的 `Host orin`，带 `BatchMode yes`、`ConnectTimeout 8`、`UserKnownHostsFile` 等参数。原有内容不动；首次写入前备份为同目录的 `config.orin-pair.bak`。
- `ssh/known_hosts`：配对测试连上后追加一条 `orin` 的主机指纹，和配置块里的 `UserKnownHostsFile` 指向同一个文件，不会再写真实 `~/.ssh/known_hosts`。解除配对不会删这条指纹。
  Orin 重装系统或换机器后指纹会变，ssh 会拒绝连接；这时在控制端点「更新指纹」：删掉这个文件里 `orin` 开头的行，再按当前配置连一次，让 ssh 用 `accept-new` 记下新指纹，并把新指纹显示在提示里。只动 `orin` 的行，其他主机记录保留；现在连不上 Orin 时旧记录也会被清掉，等 Orin 恢复后再点一次即可。
- `state.json`：配对主机、用户、client_id 和令牌（权限 600）。

因为配置不在 `~/.ssh/config`，普通终端里直接 `ssh orin` 不会用到它；需要时用 `ssh -F app/runtime/controller/ssh/config orin`，页面上的“复制 ssh 命令”复制的就是这个带 `-F` 的命令。

**被控端写入 `app/runtime/orin/`：**

- `state.json`：配对记录、配对码、网络备份（目录 700、文件 600），root 运行时也一样。
- `authorized_keys` 仍在目标账号（root 默认 `SUDO_USER`，即 sudo 的发起用户；普通用户默认自己）的 `~/.ssh/` 下：追加一行带 `orin-pair:<client_id>` 标记的公钥，权限修正为 700/600。这个文件必须留在账号家目录，否则 sshd 读不到。
- 静态 IP 模式下额外写 `nmcli` 连接配置；修改前会把原值存进 state，供“还原网络”使用。

配对码校验在所有入口（配对、查看状态、解除配对）共用同一套计数和节流闸门：失败逐渐加延时，同一来源连续 8 次失败自动换码；只读轮询本身不会触发换码，避免一个停在旧码上的页面把码换掉。配对成功后新码只显示在被控端本机页面，不再随响应返回给客户端。

**临时文件：**

- 配对时先在 `app/runtime/tmp/` 生成一份临时 ssh 配置，测试结束立即删除。
- 程序启动和退出时都会清理 `app/runtime/tmp/`、`app/runtime/` 下的 `*.tmp`，以及系统临时目录里残留的 `orin-pair-*.conf`。
- 状态、密钥、ssh 配置和备份会保留，下次打开继续用。

**日志：**

- 页面上显示最近 40 条，终端里是全部实时输出；同时追加写入对应角色的 `pair-console.log`：控制端 `app/runtime/controller/pair-console.log`，被控端 `app/runtime/orin/pair-console.log`。启动横幅和页面「日志」卡片下方都会显示实际路径。
- 用 `--state-dir` 时日志跟着状态目录走，方便演示和测试隔离。文件权限 600。
- 单文件上限 2 MB，写满后把旧文件改名为 `pair-console.log.1`（只保留一份备份），再写新的。日志只记操作（启动、配对、解除、网络、Tailscale 等），不写配对码、令牌和密码。
- 退出程序后日志保留；要清空直接删这两个文件即可，程序不会自动删。

## 解除配对

两端都可以发起：

- **被控端页面**：已配对设备 → 解除。删除该设备的公钥行和配对记录，下次连接即失败。
- **控制端页面**：解除配对。先通知被控端撤销公钥，再删本地 `Host orin` 段和状态；私钥保留。控制端用的是配对时拿到的令牌，不需要再输配对码，令牌也不能用来撤销别的设备。
- 被控端已撤销、控制端还留着配置时，页面会显示“远端已解除”，点“清理本地配置”即可。
- 令牌失效或远端拒绝撤销时，本地配置仍会清理，但页面和日志会写明“远端未撤销”及原因，需要到被控端页面手动解除。

## 远程组网（Tailscale）

两端不在同一网段、虚拟机在 NAT 后面、或者校园网做了客户端隔离时，可以用 Tailscale 组网，不用改桥接、也不用开热点。

1. 两端各装 Tailscale 并登录同一账号。页面里可以直接点按钮完成，不需要自己敲命令：
   - 被控端「远程组网」卡片：未安装时点「安装 Tailscale」（以 root 执行官方脚本，需要先在「环境准备」里切换为 root）；装好后点「登录」，页面会给出授权链接，在任意浏览器打开并登录。
   - 控制端「运行环境」卡片：未安装时点「安装 Tailscale」（调用 winget，会弹 UAC）；装好后点「登录」，按提示在浏览器完成授权。
   - 不想用按钮也可以自己执行：

   ```bash
   curl -fsSL https://tailscale.com/install.sh | sh
   sudo tailscale up
   ```

   ```bat
   winget install --id Tailscale.Tailscale -e
   tailscale up
   ```

2. 被控端页面右侧「远程组网」卡片显示本机 `100.x` 地址和在线对端，顶部出现 `Tailscale` 标记。
3. 控制端点“扫描”，会通过 `tailscale status` 自动把在线对端（最多 8 个）加入候选，结果里标 `Tailscale`；也可以直接手填 `100.x.x.x`。

默认仍然只读：只有点「安装 / 登录」按钮时才执行对应命令，平时只读取 `tailscale status --json`，不改任何 Tailscale 配置。安装和登录都不会替你授权：Ubuntu 需要 root，Windows 需要过 UAC，登录仍然要在浏览器里用同一账号确认。被控端的安装/登录接口除本机外，也接受带着配对码的远程页面（和读状态、远程解除同一凭证），方便 Orin 没接显示器时从 Windows 页面上操作。

普通用户读不到 Tailscale 状态时（页面提示权限不足），执行一次 `sudo tailscale set --operator=$USER`，或者以 root 启动本程序；Windows 控制端一般可以直接读。

Tailscale 隧道本身是 WireGuard 加密，配对码和令牌不再以明文穿过外部网络；但页面之间仍然是 HTTP，组网内也不建议放到完全不可信的环境。

## 演示模式

不改真实网络和真实 ssh 配置，适合先看界面。角色选择页在 Windows 上只开放控制端，所以本机演示完整配对准直接用两个 `--role`：

```bash
# 两个终端
python app/pair_console.py --role orin --demo --no-open --port 8765
python app/pair_console.py --role windows --demo --no-open --port 8766
```

演示数据默认也写在 `app/runtime/orin/` 和 `app/runtime/controller/`，日志文件也在同一目录，不会修改真实网络和真实 `~/.ssh`。想换位置就加 `--state-dir` / `--ssh-dir`。

控制端演示模式扫描时会额外试 `127.0.0.1:8765`，所以同一台机器上能跑通完整配对流程。演示模式同样会读取本机 Tailscale 状态，本机装了 Tailscale 时也能看到自动发现的效果；安装和登录按钮在演示模式下只返回提示，不执行。

只想看角色选择页：

```bash
python app/pair_console.py --demo --no-open --port 8770
```

## 真实环境验证

**2026-11-14，VMware 的 Ubuntu 22.04.5 虚拟机，不是演示模式：**

- 被控端以普通用户启动：`python3 app/pair_console.py --role orin --target-user <用户> --bind 0.0.0.0 --port 8765`，`authorized_keys` 写该用户自己的家目录；因为不是 root，静态 IP 和防火墙按钮保持禁用，换码只限本机页面、普通用户也能用。
- 控制端用 `--ssh-dir` / `--state-dir` 指到临时目录，没碰真实的 `~/.ssh/config` 和私钥，但 ssh 测试是真实连接。
- 结果：扫描到局域网里的被控端（`26 ms`），输码配对成功，测试返回真实的 `link-ok`；被控端 `authorized_keys` 出现 `orin-pair:<id>` 行，state 记录客户端名称与指纹，配对码自动轮换；解除配对后该行与记录被删除，控制端 `Host orin` 段清空。
- 演示模式的“配对 → 测试 → 解除”回归也通过。

**2026-11-15，v0.4.1 / v0.5.0（Windows 本机，真实 HTTP + 浏览器）：**

- 安全加固：本机状态 200；伪造 `Host` 返回 421；20 个并发错误码只有 4 个被受理、16 个返回 429（约 2.1 秒）；远程用正确码读状态 200；配对响应不再包含新码；远程用配对码解除配对 200；不带 `X-Orin-Pair` 的 POST 返回 403。浏览器里跑通了角色页 → 控制端 → 扫描 → 配对 → 解除。

## 安全边界

- 角色选择页监听 `0.0.0.0:8770`，局域网可打开，但“控制端”只接受本机点击；远程只能选“被控端”。
- 被控端页面默认对局域网开放，配对码就是入口凭证。只在需要配对时运行，配完 Ctrl+C 退出。
- 被控端普通用户就能写自己的 `authorized_keys`；改网络、写其他账号才需要 root。sshd 加固仍由 `setup.sh` 控制。
- 页面里的“切换为 root”只接受本机（127.0.0.1）请求：密码通过本机回环发到进程，只交给 `sudo -S` 校验，不写文件、不进日志；校验失败不会重启，进程保持普通用户。远程打开的被控端页面看不到这个入口。
- 控制端不会以 root 运行（角色页会禁用），避免把配置写进 root 的 `~/.ssh`。
- 网络设置、更换配对码只接受被控端本机页面（127.0.0.1）的请求，远程访问时这些按钮会被禁用。
- 控制端的 API 同样只接受本机请求：即使手动 `--bind 0.0.0.0`，远程读状态也会返回 403。
- 控制端安装 SSH 客户端走 Windows 可选功能（`Add-WindowsCapability`），会弹 UAC；只能在本机页面点按钮触发，程序不会在后台自动安装。
- 所有接口校验 `Host`：只接受 IP 字面量、本机主机名 / `<主机名>.local` 和本机地址，防止恶意网页通过 DNS rebinding 把外部域名解析到 `127.0.0.1` 后冒充本机页面；不匹配返回 421。
- 所有 POST 接口还要求页面脚本带 `X-Orin-Pair: 1` 请求头，普通跨站表单无法伪造；页面之间、控制端与被控端之间的调用也统一带上。
- 配对码校验统一节流：所有入口共享同一个闸门，失败后先等待约 0.5 秒，连续失败逐步加到 2 秒，超出直接 429；远程爆破 6 位码不再可行。
- 扫描地址、端口和远端返回的 SSH 用户名都会校验字符集，避免把换行或额外的 ssh 指令写进配置文件。
- 状态文件 600、被控端状态目录 700、`authorized_keys` 600；私钥由 `ssh-keygen` 设为 600。
- 日志文件 600，只记录操作与路径，不写配对码、令牌和密码；写满 2 MB 自动轮换，只保留一份备份。
- `app/runtime/` 里只有程序自己的文件，临时文件启动和退出都会清理，不会散落到家目录或系统临时目录。
- 解除配对不会删除控制端私钥，也不会删除目标账号。要彻底清理，删除 `app/runtime/` 对应角色目录即可。
- 「更新指纹」只删除 `app/runtime/controller/ssh/known_hosts` 里 `orin` 开头的行，其他主机的记录不动；接口只接受本机请求。
- Tailscale 默认只读：平时只执行 `tailscale status --json`；只有点页面上的「安装 / 登录」按钮才执行安装脚本或 `tailscale up`。被控端安装需要 root，登录链接要你自己在浏览器授权；控制端安装走 winget 并弹 UAC，程序不能替你确认。
- 被控端的 Tailscale 安装/登录接口只接受本机访问，或带正确配对码的远程页面；配对码校验和其他入口共用同一套节流闸门。
- 已知限制：两端通信用明文 HTTP，配对码、令牌和公钥在局域网内可被嗅探；只在可信网络使用。走 Tailscale 时外层由 WireGuard 加密，但页面本身仍是 HTTP。私钥无口令，这是免交互连接的代价。

## 常见问题

| 现象 | 处理 |
|-|-|
| 被控端按钮是灰的 | Windows 不支持被控端；Ubuntu 上普通用户也能选，改网络时在页面里切 root |
| 控制端按钮是灰的 | 当前是 root，或页面是从另一台机器打开的；改用普通用户在本机运行 |
| 「运行环境」提示 SSH 工具未找到 | 点「安装 SSH 客户端」（UAC 确认，走 Windows 可选功能），或安装 Git for Windows 后刷新页面 |
| 提示端口被占用 | `8770` 是选择页，`8765`/`8766` 是角色页；先退出占用端口的程序 |
| 页面打不开 | 确认进程还在跑；用 `--port` 只能改选择页端口，角色页端口固定 |
| 被控端页面从另一台机器打不开 | 确认绑定 `0.0.0.0`、没加 `--demo`；`sudo ufw allow from <网段> to any port 8765 proto tcp`，选择页还要放行 `8770` |
| 扫描找不到 | 手填 `orin.local:8765` 或 `192.168.55.1:8765`；先确认被控端页面能打开 |
| 跨网段 / NAT / 虚拟机能上网但扫描找不到 | 两端装 Tailscale 并登录同一账号，控制端扫描会自动列出 `100.x` 对端；见“远程组网” |
| 配对码不正确 | 用被控端页面当前显示的 6 位码；连续错 8 次会自动换码 |
| 提示“目标账号不存在” | 先在页面「环境准备」里点“安装 / 修复”，或跑 `app/setup.sh`；脚本和页面都不新建账号，也可用 `--target-user` 指定已有账号 |
| 文件都存在哪 | 都在 `app/runtime/`：控制端 `app/runtime/controller/`，被控端 `app/runtime/orin/`；启动时会打印实际路径 |
| 日志文件在哪 | `app/runtime/controller/pair-console.log` 或 `app/runtime/orin/pair-console.log`；页面「日志」卡片下方也显示路径，写满 2 MB 轮换成 `.1` |
| 普通终端里 `ssh orin` 连不上 | 配置在 `app/runtime/controller/ssh/config`，用 `ssh -F app/runtime/controller/ssh/config orin`，或点页面上的“复制 ssh 命令” |
| 提示“主机指纹变了” / REMOTE HOST IDENTIFICATION HAS CHANGED | Orin 重装或换机导致的正常现象：控制端「配对信息」里点「更新指纹」，会清掉旧的 `orin` 记录并重新连一次 |
| “远端已解除” | 在控制端页面点“清理本地配置” |
| 静态 IP 应用后页面断开 | 正常，用新地址重新打开 `http://<新地址>:8765`；“还原网络”可回到原配置 |

更完整的 ssh、账号、ROS 2 说明见 `app/agent远程连接-优化版.md`。
